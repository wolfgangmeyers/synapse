Smallest observable outcome

A router-managed worker is a direct stock-Pi RPC process that is ready only with the full accepted manifest, survives lifecycle/recovery operations, uses the same mailbox domain as tmux workers without joining their WebSocket lease protocol, and is fully operable in the existing Web UI.

The name supervisor has no special privilege. Router policy and context-derived identity—not a model or name—authorize effects.

Standing non-goals

  • No tmux replacement/removal, Pi core patch, worker sidecar, second database, generalized command/event bus, arbitrary process execution, or generalized user-auth system.
  • No per-agent credentials, transcript-text state inference, ordinary-message control encoding, best-effort live merges, or role/name privilege.
  • No terminal/console surface, alternate managed application, third history mode, or new visible source label beyond router-managed/tmux.

Dev-loop boundary

Each phase starts by loading dev-loop, has a written phase checklist, production implementation, focused automated tests and coverage, executable integration proof, review, and a clean deployable main. Later phases consume only committed contracts from earlier phases.

Do not create temporary production adapters to “get a test passing.” Fakes are test-only; final boundaries land in the first phase that needs them.

  • Child control-result contract: the manager alone creates a ctx1_ reference after the exact child AgentSession and lifecycle run bind. It is 48 ASCII characters: the prefix plus 43 unpadded base64url characters encoding 32 cryptographically random bytes, with no identity or timestamp meaning. Expose nullable context_ref only through the in-process getLifecycleSnapshotV2 result and existing subagents:lifecycle-v2 event. The root bridge keys the live binding by task/run/parent entry, strips it from child snapshot/delta router envelopes, retains it only with the pending request, and calls appendControlResultV1.
  • Result validation and append: the extension validates encoded command bounds, decoded JSON, the current request and session/process/manifest fences, and the closed payload with no coercion. The package repeats payload shape/bounds and exact owner/run/session/reference validation. The top level is {protocol,result_id,request_id,target_session_epoch,runtime_generation,manifest_sha256,status,content,details,error?}; unknown top-level and error fields fail closed, error is absent for ok and required for error, and existing 64 KiB envelope, 16 KiB content/details, structural limits, and redaction apply. Independent design review

Three-round Robot Review cap

  1. Round 1: full focused review after implementation and local proofs.
  2. Round 2: only after validated Round 1 fixes; target residual high-risk areas.
  3. Round 3: only if validated material risk remains after Round 2.

Coverage policy

Run focused coverage for every changed package plus behavior tests without instrumentation when timing-sensitive. Coverage is a branch-discovery tool, not a substitute for each AC. Every error code, fence, race precedence, retention trigger, protocol bound, and secret sink named by the phase must have a direct assertion even if line coverage is already high.

Diff budget

Only ledger files are in review scope. Preserve unrelated dirty/untracked work. No formatting churn, dependency upgrades beyond exact required package pins, shared-library redesign, generated artifact drift, or “while here” cleanup. A necessary extra file requires a written AC/necessity mapping before edit.

Conversation UI & Server Contract Architecture Audit

Comprehensive architectural audit of the Mecha-Developer Web UI conversation view, state management pipeline, attachment pipeline, and server-client protocol contract. Identifies root causes of complexity, overengineering, message formatting defects, and proposed ideal solutions.

1. Executive Summary & Root Defect Analysis

The conversation interface in web/router-ui-react has evolved through multiple iterations (legacy Mailbox disk files, V2 router HTTP polling, SSE/WebSocket streaming, and timeline event projection). This historical layering created significant architectural friction:

  • Dual Disconnected Pipelines for History vs. Live Messages: Initial message history arrives via GET /v1/conversation?agent_id=... while live streaming events arrive via WebSocket on /v1/agents. Inconsistencies between the shape of history timeline records and live streaming chunks cause message deduplication logic, envelope cards wrapping assistant turns, and lost attachments.
  • Broken Attachment URL Resolution: Attachments uploaded through /v1/attachments are referenced in message metadata, but the UI resolves them using varying relative/absolute host logic. Additionally, the router's timeline event generator omits attachment metadata from timeline rows, forcing the client to run fragile regex fallbacks against plain text.
  • Unbounded Conversation Rendering Bloat: The conversation view renders every turn without DOM windowing or cursor truncation. Because the embedded session accumulates full multi-turn scratchpads and tool results, rendering dozens of full-turn history entries slows down the browser thread and causes UI clutter.
  • Envelope Card Wrapping vs. Bubble Presentation: User and assistant messages frequently render inside heavy "envelope cards" intended for async worker mailboxes rather than conversational chat bubbles, because the rendering decision relies on ambiguous flags (e.g. source_kind and origin).

3. Quantified Architectural Deficiencies

Subsystem Symptom / Flaw Root Architectural Cause Severity
Attachment Pipeline Broken image previews, 404s, missing attachments in UI feed. HTTP transport lacks HEAD handler; timeline store fails to persist attachment metadata; UI relies on fragile body regex. High
Message Bubble Layout Assistant messages rendered in heavy mailbox "envelope cards" instead of conversational chat bubbles. Confused UI presentation model mixing async worker dispatch cards with synchronous conversation bubbles. Medium
Rendering Performance UI hangs or lags when rendering long agent sessions; excessive DOM nodes. No feed virtualization (e.g. react-window); all historical turns and tool results rendered into DOM simultaneously. Medium
State Reconciliation Flickering or duplicated messages upon page reload or network reconnect. Dual ingestion channels (REST history + WebSocket events) lacking a single authoritative monotonic cursor. High

4. Proposed Ideal Alternatives & Remediation Plan

A target architecture designed for simplicity, robustness, and performance:

1. Unified Stream Contract Contract
Replace dual REST-history and WebSocket event models with a single cursor-based event log: GET /v1/conversation/stream?cursor=123 supporting both initial chunk fetch and Server-Sent Events / WebSocket continuation.
Benefit: Eliminates duplicate reducers, deduplication hacks, and out-of-order race conditions in use-conversation.ts.
2. First-Class Attachment Schema Storage & Protocol
Include a dedicated attachments: [{id, url, contentType, size}] array in every timeline event. Support HEAD requests on /v1/attachments/* and generate full canonical URLs server-side.
Benefit: Completely removes regular-expression text parsing from MessageBubble.tsx and prevents 404 rendering errors.
3. Pure Bubble Conversation Hierarchy Design System
Enforce a strict separation between Chat Feed (pure user/assistant bubbles) and System Telemetry (collapsible tool runs and status pills). Remove envelope card styling from the chat stream.
Benefit: Immediate visual clarity matching modern conversational UI standards without jarring envelope cards.
4. Virtualized Message Feed Performance
Introduce windowed rendering for MessageList using lightweight virtual scrolling, rendering only active viewport elements while preserving scroll-to-bottom mechanics.
Benefit: Fast, constant-time DOM rendering regardless of session length or number of subagent tool calls.

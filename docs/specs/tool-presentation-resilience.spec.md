# Spec: Tool Presentation Size Limit Resilience

- **ID**: `SPEC-TOOL-PRESENTATION-RESILIENCE-001`
- **Status**: `Active`
- **Domain**: `AgentManagement`
- **Target E2E Suite**: `tests/e2e/tool-presentation-resilience.spec.ts`

## 1. Intent & User Outcome

When an agent executes a tool call, the tool's activity status in the Web UI transitions reliably from "Running" (`active`) to a terminal state (`success` or `failed`). Long thinking traces or companion text generated by the model during the turn must never cause presentation metadata serialization to exceed size limits or fail validation. Even in the event of unexpected presentation validation or serialization errors, the system gracefully falls back to a clean minimal terminal presentation, guaranteeing that tool calls never get permanently stuck in the "Running" state.

## 2. Core Invariants

1. Active thinking state is cleared as soon as a tool call begins or tool execution starts, preventing stale thinking text from previous turns or earlier steps from leaking into subsequent tool presentations.
2. Presentation JSON stored in `presentation_json` MUST stay strictly within database and transport size limits (maximum 2048 bytes). Any `Thinking` or `CompanionText` included in `ManagedHistoryPresentation` is sanitized and bounded to prevent overflow.
3. If recording history completion with full presentation metadata fails (due to serialization, sizing, or validation errors), the system MUST gracefully fall back to recording with a safe minimal presentation (e.g. `Kind: "tool"`, `ToolName: toolName`, `Outcome: "success"` or `"failed"`, `Summary: ...`) so the database record transitions out of `active` and notifies the UI.
4. Tool invocations in Complete history MUST ALWAYS reach a terminal outcome (`success`, `failed`, or `interrupted`) upon completion; they MUST NEVER remain in `active` state after tool execution has concluded.

## 3. User Scenarios

### Scenario: [TPR-001] Tool call completes successfully with long thinking and companion text
- **User Goal**: View real-time tool completion in the conversation timeline without stale "Running" badges even when model output is verbose.
- **Given**:
  - A managed agent is running in embedded mode.
  - The model generates extensive thinking text and assistant companion text before invoking a tool.
- **When**:
  - The tool execution begins and finishes.
- **Then**:
  - The active thinking state is reset when the tool call starts.
  - The tool presentation record bounds companion and thinking text so presentation JSON remains well under the 2048-byte limit.
  - The tool activity card transitions from running to terminal success/failure in the timeline.

### Scenario: [TPR-002] Graceful fallback on presentation write failure
- **User Goal**: Ensure tool completion is recorded even if custom presentation metadata contains invalid or oversized text.
- **Given**:
  - A tool invocation is currently recorded as `active` in `managed_complete_history`.
- **When**:
  - Recording the completion entry with full presentation metadata encounters an error.
- **Then**:
  - The store/runtime falls back to recording with a safe minimal presentation.
  - The tool entry in `managed_complete_history` is updated with outcome `success` or `failed`.
  - The UI receives the completed history event and updates the tool status out of "Running".

# Claude default: managed RPC boundary inventory

CD-005 scope: repository callers and owned runtime, not an inventory of external API consumers.

- `POST /v1/managed-agents` accepts `runtime: "rpc"`; `router-proxy/internal/transport/managed_http.go` also defaults omitted runtime to RPC. External REST clients can therefore request RPC explicitly or implicitly.
- `web/router-ui-react/src/components/ManagedAgentDialog.tsx` explicitly launches embedded. Its transport and protocol types also permit RPC (`http-client.ts`, `protocol/types.ts`), so other UI callers can supply it. Acceptance runners and E2E/Go fixtures exercise managed RPC, including `web/router-ui-react/tests/acceptance/bcb-managed-rpc-release-runner.mjs` and `router-proxy/internal/transport/managed_launch_behavioral_functional_test.go`.
- `router-proxy/internal/managed/supervisor.go` defaults direct manager requests to RPC too. Existing RPC execution and recovery rely on the managed Pi binding. `process.go` starts Pi `--mode rpc` with the mecha RPC extension and Pi subagent extension; `pi-extensions/mecha-rpc` implements the associated Pi custom-message protocol. Claude's managed process instead uses Claude CLI `--input-format stream-json --output-format stream-json` and its own MCP bridge (`claude_code_process.go`). These are different managed protocols; the Claude adapter does not implement the Pi RPC binding.
- Therefore the current manager rejects effective Claude with RPC and directs callers to embedded before launch reservation. `tests/e2e/claude-rpc-boundary.spec.ts` checks explicit and saved selection and the omitted-runtime REST default, with isolated router/proxy/SQLite and the fake CLI. This does not establish compatibility for external clients or prove a real Claude CLI contract.

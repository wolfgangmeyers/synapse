Router guide

Router architecture

The router stores messages in SQLite and runs managed agents using its embedded runtime. Supervisor-started tmux workers have a separate process owner.

The former managed Pi RPC mode and the repository's mecha-rpc and mecha-messaging extensions are retired. Embedded operation and native Pi subagents still have Pi-related dependencies. Other detail pages may describe the historical RPC design; check their claims against current code.

A few names used in this guide

Managed root

A router-managed main agent, distinct from its children. Current managed launches use the embedded runtime, not a Pi RPC subprocess.

Managed HTTP · Embedded runner

Supervisor-started tmux worker

A separate process started by the supervisor. The router does not own its process; do not assume the deleted messaging extension delivers its mail.

Queue, delivery, and fence

SQLite stores messages and delivery state. An eligible source can determine a delivery target; otherwise mail normally waits. Fences bind managed work to the current owner and session generation.

Agents and mail

Managed launches use /v1/managed-agents. Senders use /v1/messages; compatible worker clients connect through /v1/agents. The UI uses managed HTTP controls and live WebSocket updates. Managed controls are unauthenticated; restrict access to trusted clients.

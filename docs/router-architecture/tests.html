There are behavioral and installed-Pi tests. Each covers a different boundary. A green result for one path does not establish another.

Behavioral coverage by flow

Request to ready Pi

The test makes an HTTP launch request, checks the SQLite agent, checks readiness before the initial prompt, and checks replay. It starts a real OS child process group. That child is a deterministic fake Pi speaking JSON-RPC, not installed Pi.

Root control

Router to Python host

The combined test drives a real HTTP router, manager, SQLite store, and Python host adapter. It checks mailbox and reminder effects, replay, conflicts, and a decoy router. The process factory and RPC client are injected doubles. No installed Pi emits its root requests in this test.

02

Coverage limits and useful next tests

Proposals below target seams not joined by the cited tests. They do not imply the repository has no end-to-end tests.

Proposal 01

Root tool to real tmux launch

Drive installed Pi through a provider-issued mecha_worker launch. Keep the real router, Python adapter, supervisor state, lifecycle script, tmux, and mailbox bridge. Verify the queued response, one new tmux identity, delivered control result, and later worker instruction. The installed-Pi test currently uses manager-owned goal status. The combined Python test injects process and RPC.

managed_root_control_native_test.go:414-461
domain1_behavioral_functional_test.go:160-173, 358-389
worker_lifecycle.py:91-133
Proposal 02

Crash between tmux start and host save

Pause after worker_launch.py creates a window, then kill the host adapter before it saves requests.json. Restart control reconciliation. Assert ROOT_OPERATION_UNKNOWN, exactly one tmux window, and no second launch. A mocked subprocess cannot prove the real window survives this gap.

managed_root_control.py:602-641
test_managed_root_control.py:69-93, 112-143
Proposal 03

Lost result receipt after worker start

Complete a real tmux launch, persist the host result, then interrupt the router or Pi before the append receipt is stored. Reconnect and verify one worker, one control result, and one delivered transcript entry. The existing receipt code reconciles this boundary, but the combined router test supplies its own RPC receipt.

root_control_manager.go:539-622
domain1_behavioral_functional_test.go:80-142, 431-449

Interpretation: use deterministic providers and local fixtures at the external boundary. Keep real owned components together when validating a cross-boundary flow.

Architecture

The router stores messages and managed state in SQLite, serves HTTP and WebSocket clients, and runs managed agents with its embedded runtime.

The former router-managed Pi RPC process and the repository's mecha-rpc and mecha-messaging extensions are retired. This does not retire Pi-related dependencies used by embedded operation or native Pi subagents. Other pages in this architecture set may still describe the old RPC design and need review.

System map

Senders use /v1/messages; worker clients connect to /v1/agents. The router records and routes mail in SQLite. The browser uses managed HTTP routes and /v1/ui-live for live state. The optional reverse proxy forwards HTTP and WebSocket traffic without owning router state.

Router transport · Delivery store · Proxy and launcher

Managed and external workers

A managed launch through /v1/managed-agents defaults to embedded; the current route accepts that runtime. The router owns the embedded agent lifecycle and its fenced owner binding. Embedded is not a Pi process launched with --mode rpc.

Separately, supervisor-started tmux workers have their own process lifecycle. WebSocket delivery remains a router interface, but the deleted repository messaging extension must not be assumed to provide it.

Managed HTTP · Embedded runner · Worker WebSocket

Queue and persistence

SQLite stores messages and delivery state. A fixed delivery target is selected when an eligible source is available; queued messages may wait for a recipient. Embedded ownership is bound to the saved agent/session generation. Restart recovery must respect those bindings rather than treating retired RPC transcript receipts as current embedded delivery.

Delivery store · Embedded store

Controls and boundaries

The browser calls managed HTTP controls; the router persists state and publishes UI updates. Managed controls are unauthenticated: CORS is not access control, so restrict access to trusted clients.

The embedded runtime retains Pi-related dependencies, including the provider runtime packages in auth-helper and the configured pi-subagents entry. Do not remove them merely because RPC mode is retired. Historical RPC acceptance runners require separate migration; see the acceptance inventory.

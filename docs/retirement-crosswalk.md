### Specific plan acceptance still unmapped

These details remain in the full plans and are not closed by the evidence summary:

- **Search:** credential precedence (Pi then Codex fallback), refresh/writeback safety, API override, exact backend headers/request fields, synthesized output/sources/query formatting, and tool/store/workflow inventory registration. Existing auth code may differ from the original design; parity needs explicit mapping.
- **Scratchpad:** pinned preservation, exactly one threshold, strict before-ID timestamp cutoff, caller-only tool isolation, HTTP validation/not-found error semantics, exact deletion counts, and explicit-only truncation with **no background pruner**. API tests do not automatically establish model-tool parity or every edge case.
- **Budget:** shared three-credit pool for both readers, refill one/minute capped at three, invalid ID without debit, terminal retrieval free, and removal of old warning/throttle behavior. Viewer snapshot E2E does not exercise these acceptance conditions.
- **Schedules:** timezone defaults (API UTC / browser local authoring), automatic next-run computation on create/update, legacy data migration, and no cron UI/storage/API exposure, alongside all cadence permutations and timezone/DST cases. Existing selected firing/UI tests are not a complete acceptance map.

# Embedded Pi Go: implementation plan

**On hold.** This is a plan only. Do not start implementation until Wolfgang explicitly says go. The [requirements](embedded-pi-go-requirements.md), [technical spec](embedded-pi-go-technical-spec.md), and [I4/M2 gate](embedded-pi-go-i4m2-gate.md) define the contract and evidence; this stub does not replace them.

## First opt-in slice

- Use one in-process Go runner type for one **new** embedded root and a minimal second, independent embedded worker. Give each its own ID, parent relationship, mailbox, session/epoch, model, run generation, and launch/stop/restart lifecycle. The existing WebUI launch-managed-worker button/API must create that embedded worker, then support launch → mail → reply → restart through its identity. Do not route this launch to tmux or implement native recursive subagents.
- Keep SQLite authoritative for accepted mail, exact-attempt delivery ACK, ordered conversation and compaction checkpoints, identities, operations, and worker state. Commit the exact intended-session entry before processing ACK; acceptance remains a separate SQLite commit. Recover prior context in order after a crash. Mark interrupted turns and unknown external effects visibly, with no blind replay. Attribute one settled reply to its initiating mail/turn, not a stream fragment or the latest sender.
- Use one router-owned Codex OAuth login and durable credential store for all embedded agents, with serialized refresh and durable rotation before use. Support Codex Responses streaming/tools. Filter model listing and validate each agent's selection against that shared auth. Persist requested selection immediately, but apply it at the next turn boundary without interrupting an active stream.
- Install the approved fixed tools before the first model request. Keep built-in `read`, `bash`, `edit`, and `write` usable under safe cwd/path/command policy, without inline-tool allowance. Implement `goal` set/status/off, `goal_snooze`, `mecha_reminder` create/list/update/delete, `mecha_mailbox_send`, `mecha_worker` launch/list/send/cleanup, and `mecha_context` status/manual compact plus fixed-policy automatic compaction. Share a durable, fenced SQLite wakeup queue for reminders, interrupted-turn notices, and bounded goal reevaluation. Return bounded direct Go handler results in the same tool turn; persist external-effect intent/result and checked tool-result context before model continuation. Do not claim a queued result is completion.
- Preserve WebUI-facing HTTP/WS fields, behavior, and live snapshots/deltas with **no WebUI code changes**, including launch, restart, models, auth, context/history and worker projections. Preserve full transcript versus bounded quiet/complete histories. Fence late generations and repair reconnect gaps from saved state. Keep the existing RPC root and supervisor-owned tmux/WebSocket workers available for mixed mail and opt-in rollback; do not reinterpret or import their sessions.

## Gates before calling the slice end-to-end

1. Reproduce the [pinned I4/M2 failure](embedded-pi-go-i4m2-gate.md) as documented: recorder IDs and `Run`/`Close` success do not prove durable writes. Its historical transcript-as-mail-receipt interpretation is superseded; **never** use it as a durable mail receipt. First prove the audited SDK's checked SQLite entry capture/load and compaction pre-publication commit seams, including first prompt before assistant output, ordered reopen, manual/automatic checkpoint and injected write failures. These seams are proposed changes, not present APIs. Record a reproducible supported Go build/dependency strategy.
2. Prove SQLite mail acceptance versus exact-session append/ACK, crash reconciliation, interrupted-turn notices, unknown worker/tool effects, one worker and one reply despite retries, and safe no-replay behavior. Exercise root and worker restart, fenced reminder/goal wakeups, direct handler results, builtin safety, compact no-op/failure, and full/quiet/complete projections with deterministic fixtures.
3. Prove the router-owned Codex auth/provider path, shared serialized refresh, secret isolation, real request/tool boundaries, and authorized model listing/selection before claiming end-to-end. Test idle and active model changes and reconnect. The existing `restartManaged` model action and single `model`/`current_model` projection must truthfully represent requested-but-queued versus active selection using existing fields. If they cannot, flag the first-slice zero-WebUI-change gate **unresolved**; do not claim compatibility or silently alter RPC behavior.
4. Prove the existing WebUI launch-managed-worker button/API creates an embedded worker, and verify launch → mail → reply → restart without WebUI changes. Cover saved operation replay, runtime limits, failure containment, router crash/reopen, mixed tmux mail and clean opt-in RPC rollback. A model catalog row or a healthy router alone is not a ready agent.

## After the slice

Finish the remaining [requirements acceptance gates](embedded-pi-go-requirements.md#acceptance-gates) and [technical-spec verification](embedded-pi-go-technical-spec.md#implementation-gates-and-verification-plan), then decide on wider opt-in and cutover from evidence. Keep old RPC/tmux paths through rollback. After cutover, RPC worker internals may retire only if unneeded; no blanket RPC parity, old Pi-session import, tmux migration, or native-subagent requirement for v1.
